# Инженерные решения

1. Папка первоначально содержала только исходные материалы. Предыдущего Python/ZIP, Git и инструкций AGENTS.md не найдено. Исходные файлы не изменялись.
2. React + TypeScript + Vite + React Router + TanStack Query; FastAPI/Pydantic. Версии зафиксированы в pnpm-lock.yaml и requirements.lock.txt. Никакого внешнего AI-агента в runtime.
3. SQLite WAL через стандартный sqlite3, транзакционные версионированные SQL-миграции вместо предложенных SQLAlchemy/Alembic: один локальный процесс, прозрачный BEGIN IMMEDIATE для бюджета и version checks. Миграция 001 идемпотентна; DB вне исходников.
4. Один worker ThreadPoolExecutor; заявки сохраняются до выполнения. После crash незавершённые runs/jobs получают failed и доступны для повторного запуска; резервы неизвестного исхода списываются консервативно. Автоматически повторять платную задачу после crash нельзя.
5. Приоритет PDF над новой светлой композицией сохранён для брифа/карты. Новые служебные экраны светлые. Поле вопроса/чат исключены по прямому уточнению. Карта показывает возможные механизмы, не выдуманные цепочки поставщиков.
6. Компании только выбранные 3. Полные исходные CSV просканированы, UI/API работают с их минимальными снимками и агрегатами. Сырые связи физлиц не отправляются модели и не выдаются через API.
7. Фактические утверждения в MVP должны быть точными выдержками из доступных chunks. Наличие ссылки само по себе не считается поддержкой. Содержательные перефразы live до расширения verifier могут быть отклонены: предпочтение строгой проверке.
8. Учебные PDF проверяют RAG, но не наполняют bank_view. Версия модели должна совпасть с отдельно подтверждённым ID из инструкции организаторов; алиас не используется как угаданный API ID.
9. Поддержка произвольного RSS/автообновления не включена без согласованных feeds. Импорт URL/text/PDF/CSV/ZIP работает отдельно. Локальный OCR не установлен; скан получает needs_ocr.
10. Только localhost; публикация и банковские операции не выполняются. Docker публикует порт только на 127.0.0.1. Demo picker не является банковской авторизацией.
11. На текущей macOS прямые compiler reads отдельных файлов в Documents зависали; чистая копия вне Documents успешно прошла typecheck/build. scripts/build копирует актуальный frontend и lock-файлы в отдельную временную папку, устанавливает зависимости из локального pnpm cache, компилирует там и возвращает dist. Это обходит дефект среды, не меняет исходники или API. Docker компилирует напрямую в /app.
12. Каждый новый run сохраняет immutable profile_snapshot; старый overview и ссылка на provenance показывают профиль на момент анализа, даже после нового CSV. Роль истории берётся из run, не из текущих предпочтений.
13. Текущий preview использует проверенную runtime-копию вне Documents. Игнорируемый .runtime-dir подхватывается scripts/dev при наличии этой копии; БД/загрузки остаются в исходном проекте, .env читается оттуда через python-dotenv без копирования секрета. Это локальная настройка среды, не часть исходных fixtures. Без cache path dev работает в корне обычным способом.

## 26.10.2026 — Google API и техническая сдача

По прямому указанию владельца текущий провайдер Google, модель
`gemma-4-26b-a4b-it`. Разрешение на обезличенный контекст сохраняется.
Официально подтверждены точный ID и бесплатные вход/выход. Стоимость Google
рассчитывается по этому тарифу, так как usageMetadata не содержит счёт.
Метаданные проверяются до генерации; API-ключ в заголовке, только локально.
Контекст сокращён, полные исходники не меняются. Автообновление и повторы
не включаются. Таймаут 240 секунд нужен для девяти разборов в одном ответе.
История Git начинается с честного текущего checkpoint 1.3, прежняя история
не восстанавливается задним числом. Публичная публикация без согласия не выполняется.

## 26.10.2026 — пользовательские тексты и Docker

По указанию владельца техническое имя модели не показывается на пользовательских
экранах: используются «AI-анализ» и «Локальные правила». Исходные ответы и метод
сохраняются в БД для аудита. Формальная фраза о соответствии профилю заменяется
понятным перечнем недостающих данных об объектах и регионах; основания не меняются.
Docker Desktop после установки проверяется в отдельном проекте и volume на порту
8002, чтобы не затронуть рабочую базу и сервер 8000. Ключ в тестовый контейнер не
передаётся. Для macOS без CLI в PATH scripts/docker-demo подхватывает Docker.app.

Git в Documents возвращал Operation timed out при обновлении index и чтении
старых объектов. Исходные два технических чекпойнта сохранены целиком в
data/local/git-before-release. Передаваемая история начинается с честного
снимка уже проверенных исходников 1.4 и следующей фиксации материалов сдачи;
история разработки задним числом не создаётся. Метаданные рабочего репозитория
размещены отдельно в data/local/git-v14, корневой .git указывает на них.
