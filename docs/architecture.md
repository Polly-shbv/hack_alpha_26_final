# Архитектура

React/TypeScript/Vite обслуживает интерфейс; React Router поддерживает прямые ссылки и историю. TanStack Query разделяет запросы по company/role/run и передаёт AbortSignal; смена компании не позволяет старому ответу заменить новую страницу. FastAPI предоставляет типизированный OpenAPI `/docs`, Pydantic проверяет входы и structured output.

SQLite WAL хранит профили, источники/chunks/FTS5, события, immutable insight versions, runs и safe tool results, saved/feedback, session preferences, import jobs, уточнения профиля и budget ledger. Миграции в `backend/migrations`. SQL транзакции и foreign keys; BEGIN IMMEDIATE сериализует резервирование. Локальные загруженные PDF — `data/local/uploads`, имена только server-generated IDs; исходные пользовательские имена не используются как путь.

Оркестратор: plan → company context → active dated events → bank FTS → transparent ranking → deterministic fixture / approved API → extractive evidence validation + targeted retrieval до 2 попыток → атомарная публикация. Сохраняется журнал инструментов и evidence IDs, приватные рассуждения не показываются. Публикуется один согласованный snapshot; old run не перезаписывается. Отмена запрещает новые вызовы и публикацию partial. Timeout 120s проверяется между этапами; HTTP LLM timeout 30s.

В памяти один worker; задания durable в SQLite. На restart незавершённое становится failed; пользователь может повторить, прежний завершённый snapshot остаётся. Это локальный MVP, не распределённая очередь. Масштабирование: вынести durable queue/worker, PostgreSQL и object storage; сохранить контракты и ограничения бюджета.

Режимы разделены полем mode во всех источниках/событиях/runs. Fixture не вызывает API. Live не переключается на fixture при ошибке; exact model ID и тариф обязательны. До вызовов резервируется полный run cap (default 25 ₽), каждый вызов дополнительно проверяет верхнюю оценку UTF-8 bytes/max_output и остаток. После неизвестного исхода резерв списывается консервативно. Местный ledger не видит расход ключа другими процессами команды; внешний provider quota всё равно необходим.

AI-помощник — отдельный чисто интерфейсный modal. У него нет backend, adapter, токенов или истории.

Версия 1.1: `content.py` выделяет признаки материалов; `stories.py` группирует близкие сообщения и проецирует их на доступный корпус/дату; `feeds.py` собирает RSS/Atom; `relevance.py` ранжирует по признакам без привязки к ID; `interpretation.py` обрабатывает новые тексты общими локальными правилами. `corpus.py` проверяет манифест и OCR-sidecars банковских материалов. Дополнительные основания действительно вызывают пересчёт. Полное описание — middle-steps.md.

Загрузки по умолчанию хранятся рядом с выбранной `ALFA_DB`, в `uploads/`; можно явно задать `ALFA_UPLOAD_DIR`. Поэтому изолированные тестовые базы больше не записывают файлы в пользовательское хранилище. Проверка публичного HTTPS использует certifi или явно заданный `SSL_CERT_FILE`, не отключая TLS-проверку.


## Версия 1.2 — непрерывный локальный сбор

Один процесс Uvicorn запускает фоновый Worker. SQLite хранит реестр подписок, очередь циклов, версии URL, цели анализа, отпечатки корпуса, кэш проверенной интерпретации и квоты бесплатной модели. Транзакционная lease предотвращает второй одновременный сборщик; после сбоя прерванные циклы видны в истории. Отдельные Redis, cron и Node-процесс сборщика не требуются. Vite нужен только в режиме разработки; переносимый пакет обслуживает интерфейс тем же API.

Доступ к источникам проходит через DNS-pinned fetch_public; разрешены только публикации выбранного издателя. Простой RSS-анонс отличается от полного HTML. Корпус банка обновляется через подтверждённый локальный манифест и отдельные наблюдения за официальными PDF. Даты без основания не назначаются.

После изменения корпуса создаются отдельные snapshots компаний/ролей. Браузер опрашивает состояние активного сбора каждые пять секунд и инвалидирует представления после появления готового результата. Старый snapshot остаётся доступным. Расходы бесплатной модели дополнительно ограничены нулевым max_price и точным ID; профили не покидают компьютер без allow_external_context. Полный сценарий и ограничения — realtime-demo.md.

## Версия 1.3 — ручной пакет

Расписание и автоматический диспетчер целей выключены. Коллекция по кнопке создаёт один analysis_batch. Локальное планирование выбирает до девяти пар для трёх компаний; единый контекст дедуплицирует события и банковские фрагменты. Единственный ответ проверяется по каждой паре, затем все истории публикуются атомарно. Только подтверждённые пары попадают в кэш. Ошибки/пропуски используют локальные правила без повторного вызова. Перезапуск прерывает пакет, а не повторяет генерацию. Согласие на передачу обезличенного контекста получено 26.10.2026.

## Выпуск 1.4

Провайдер текущего запуска — прямой Google API, native generateContent и
usageMetadata. Адаптер ограничен точным бесплатным ID Gemma. Код Google и
OpenRouter разделяет форматы авторизации/ответа; состояние cooldown учитывает
провайдера. Малые выдержки и минимальные признаки уменьшают пакет. Генерация
одна, максимум 240 секунд; некорректные пары дают локальный результат с меткой.
Контракты, даты, валидация оснований и атомарная публикация остаются общими.
